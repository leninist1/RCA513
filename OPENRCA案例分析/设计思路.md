# 基于情绪向量的 Meta-Controller 设计思路 v2

## 一、范式转变

```
旧范式（被动验证）:
  Engine → 固定候选列表 → Strategy 验证裁决 → 取 composite 分数最高的

新范式（主动推理）:
  MetaController 维护 HypothesisList（信念状态）
    ├─ Step: 评估当前信念 → 选择 (工具, 目标) → 执行 → 更新信念
    ├─ HypothesisList 操作: add / reorder / reserve / recall / eliminate
    ├─ 工具: ENGINE_SCAN / ENGINE_RECOVER / VERIFY_S1~S5 / GRAPH_EXPAND
    └─ 信息增益收敛 → 停止
```

**候选列表不再是引擎一次性计算、策略微调的静态快照。** 它是一个活的信念状态——meta-controller 通过调用引擎和策略获取信息，持续对候选列表施加增删、重排、升降级操作，使信念朝着信息增益最大的方向前进。

## 二、HypothesisList：动态信念状态

### 2.1 数据结构

```python
@dataclass
class Hypothesis:
    entity: str
    layer: str                    # "node" | "service" | "pod" | "unknown"
    confidence: float             # 综合信念分数 [0, 1]
    status: str                   # "active" | "reserved" | "eliminated"
    engine_score: Optional[float] # 反事实恢复分数（可能尚未计算）
    anomaly_score: Optional[float]
    verdicts: Dict[str, Verdict]  # {dimension: Verdict}
    evidence: List[Dict]          # 累积证据
    reason_family: str            # 推断的原因族
    added_by: str                 # "engine_scan" | "graph_expand" | "strategy_S3"
    iteration_added: int
    last_updated: int
    # "为什么是这个置信度"的可追溯理由
    confidence_rationale: str

class HypothesisList:
    active: List[Hypothesis]       # 按 confidence 降序，当前活跃候选
    reserved: List[Hypothesis]     # 低置信度但未排除的储备池
    eliminated: List[Hypothesis]   # 明确排除的候选
    history: List[Operation]       # 操作日志，支持回溯
```

### 2.2 核心操作

```python
class HypothesisList:
    def add(self, hypothesis: Hypothesis, target: str = "active"):
        """将新候选加入 active 或 reserved。"""

    def update_confidence(self, entity: str, new_confidence: float, reason: str):
        """更新某个候选的置信度，记录变更理由。"""

    def reorder(self):
        """重新计算所有 active 候选的 confidence 并排序。
        confidence 由 engine_score + verdicts 综合得出。"""

    def reserve(self, entity: str, reason: str):
        """active → reserved。置信度不足但仍有可能。"""

    def recall(self, entity: str, reason: str):
        """reserved → active。后续推理发现了新证据。"""

    def eliminate(self, entity: str, reason: str):
        """→ eliminated。明确反证排除。"""

    def top(self, n: int = 3) -> List[Hypothesis]:
        """返回 active 中前 n 个候选。"""

    # ---- 信念分布统计 ----
    def entropy(self) -> float:
        """active 候选 confidence 分布的归一化熵。"""

    def concentration(self) -> float:
        """1 - entropy。高值 = 信念集中在少数候选。"""

    def gap(self) -> float:
        """#1 和 #2 之间的 confidence 差距。"""

    def conflict_ratio(self) -> float:
        """有 support 也有 refute 的候选占比。"""

    def verified_ratio(self) -> float:
        """至少有一个 verdict 的候选占比。"""

    def fragility(self) -> float:
        """#1 被 #2 翻盘的概率估计。基于 gap + #2 未验证维度数。"""
```

### 2.3 Confidence 计算

```
confidence(entity) = f(
    engine_score,           # 反事实恢复分数（若已计算）
    anomaly_score,          # 异常分数（若 entity 尚未 ENGINE_RECOVER）
    +0.10 × n_supports,     # 每个 support +0.10
    -0.15 × n_refutes,      # 每个 refute -0.15
    -0.05 × n_inconclusive, # 不明确 = 轻微负信号
    × status_penalty,       # reserved 有折扣因子
    × coherence_bonus,      # 证据一致（有 support 无 refute）= bonus
)
```

confidence 不是简单加法——它反映的是**信念的集中程度**。当 #1 拥有 3 个 support 且 #2 有 2 个 refute 时，两者的 confidence 差距应该很大。当 #1 和 #2 都没有任何 verdict 时，两者 confidence 都应接近 engine_score。

## 三、Meta-Controller 的工具箱

meta-controller 不直接计算任何东西。它通过调用工具获取信息，然后更新信念状态。

### 3.1 工具接口

```python
@dataclass
class ToolResult:
    tool_name: str
    target_entities: List[str]
    cost: ResourceCost
    # 工具返回的信息，类型取决于工具
    data: Any  # Dict[str, recovery_score] | VerificationResult | List[str]


class BaseTool(ABC):
    """工具接口。未来算法工具和 LLM Agent 工具共用此接口。"""

    @property
    @abstractmethod
    def name(self) -> str: ...

    @property
    @abstractmethod
    def cost_profile(self) -> ResourceCost: ...

    @abstractmethod
    def execute(self, state: "ControllerState",
                target: ToolTarget) -> ToolResult: ...

    @abstractmethod
    def estimate_information_gain(self, state: "ControllerState",
                                   target: ToolTarget) -> float:
        """估计在该目标上执行本工具的预期信息增益。"""
```

### 3.2 九个工具

| 工具 | 作用 | 产出 | 影响 HypothesisList |
|------|------|------|-------------------|
| **ENGINE_SCAN** | 对指定实体批量运行反事实分析 | `{entity: recovery_score}` | add 新候选到 active/reserved；更新已有候选的 engine_score |
| **ENGINE_RECOVER** | 对单个高优先级候选做精确恢复评估 | `recovery_score + degradation_details` | update_confidence |
| **VERIFY_S1** | 排他性验证——异常是否显著强于 peer？ | `{entity: Verdict}` | update_confidence；可能 reserve/eliminate |
| **VERIFY_S2** | 局部强度验证——跨模态一致性 + 时间优先 | `{entity: Verdict}` | update_confidence |
| **VERIFY_S3** | 传播溯源——候选是源头还是受害者？ | `{entity: Verdict} + 可能发现的上游实体` | update_confidence；可能 add 新候选 |
| **VERIFY_S4** | 层级消歧——node/service/pod 哪一层？ | `{entity: Verdict + layer_label}` | update_confidence；可能改变候选的 layer 认知 |
| **VERIFY_S5** | 语义锚点——日志/追踪中有硬证据吗？ | `{entity: Verdict + anchor_type + reason_family}` | 强信号，可能直接 confirm 或 eliminate |
| **GRAPH_EXPAND** | 沿依赖图向上/下游/双向扩展 | `新实体列表` | add 到 active 或 reserved |
| **PEER_LOOKUP** | 找到同层 peer 实体 | `peer 列表` | 对 peer 做 ENGINE_SCAN 可能发现新候选 |

### 3.3 工具成本

| 工具 | api_calls | compute | 典型信息增益 |
|------|-----------|---------|------------|
| ENGINE_SCAN(N) | 0 | 0.1s × N | 高（初始时）→ 低（后期） |
| ENGINE_RECOVER | 0 | 0.5s | 中（精确评估） |
| VERIFY_S1 | 0 | 0.01s | 中（排他性检查） |
| VERIFY_S2 | 0 | 0.1s | 中（深度验证） |
| VERIFY_S3 | 0 | 0.05s | 中-高（可能发现新候选） |
| VERIFY_S4 | 0 | 0.01s | 低-高（取决于数据集的层级复杂度） |
| VERIFY_S5 | 0 | 0.02s | 极高（命中时）/ 极低（无锚点时） |
| GRAPH_EXPAND | 0 | 0.05s | 变化（取决于图结构） |

## 四、情绪向量：从信念分布涌现的 6 维状态空间

### 4.1 情绪向量定义

```
e ∈ [0,1]⁶

e₁ 笃定感 Conviction    信念集中在少数候选的程度（= concentration × gap_factor）
e₂ 好奇感 Curiosity      未探索空间的价值（= (1-coverage) × (1-conviction)）
e₃ 困惑感 Perplexity     证据内部矛盾程度（= conflict_ratio × leader_conflict_penalty）
e₄ 警觉感 Vigilance      排名翻转风险（= fragility × vigilance_urgency）
e₅ 饱足感 Satiety        边际信息增益递减信号（= coverage × diminishing_factor）
e₆ 焦虑感 Anxiety        资源压力 × 不确定性（= pressure × (1-conviction)）
```

### 4.2 情绪向量是纯函数

情绪向量不从独立状态变量维护——它每一轮都从 `HypothesisList` 的分布特性中**重新计算**。这意味着：

```python
def compute_emotion_vector(hypothesis_list: HypothesisList,
                           budget_remaining_ratio: float,
                           iteration: int, max_iter: int) -> EmotionVector:
    # 所有维度从 HypothesisList 的统计量统一计算
    concentration = hypothesis_list.concentration()
    coverage = hypothesis_list.verified_ratio()
    conflict = hypothesis_list.conflict_ratio()
    fragility = hypothesis_list.fragility()
    gap = hypothesis_list.gap()
    ent = hypothesis_list.entropy()

    conviction = concentration * sigmoid(gap * 5)
    curiosity = (1 - coverage) * (1 - conviction)
    perplexity = conflict * (1.5 if leader_has_refute(hypothesis_list) else 0.7)
    vigilance = fragility * (1.3 if leader_has_refute(hypothesis_list) else 1.0)
    satiety = coverage * sigmoid((iteration - 2) * 0.8)
    anxiety = (1 - budget_remaining_ratio) * (1 - conviction) * 1.5

    return EmotionVector(conviction, curiosity, perplexity,
                         vigilance, satiety, anxiety).clamp()
```

### 4.3 情绪向量的向量性质：三种原生操作

情绪向量之所以叫向量，不是因为维度多，而是因为它支持**只有向量空间才有的操作**：

#### 操作 1：余弦相似度 —— 类比检索

```
cos(e_current, e_historical) → 找到历史上与新状态最相似的决策时刻
→ 参考历史上那个时刻采取了什么动作，结果如何
```

```python
def similarity_guided_action(e_now, trajectory_memory, hypothesis_list):
    # 在历史轨迹中找最相似的 k 个情绪状态
    neighbors = trajectory_memory.query(e_now, k=20,
                                         filter_system=hypothesis_list.system)
    # 按相似度加权聚合历史上后续动作的成功率
    action_scores = {}
    for rec in neighbors:
        weight = e_now.cosine_similarity(rec.emotion_before) * rec.outcome_weight
        action_scores[rec.action] = action_scores.get(rec.action, 0) + weight
    return max(action_scores, key=action_scores.get)
```

#### 操作 2：效果向量 —— 预测动作的推动方向

```
Δe = e_after - e_before   ← 这是某个工具执行前后的情绪变化向量
                          ← 累积多次后，每个工具在每个系统上有典型 Δe

e_predicted = e_now + Δe_tool   ← 预测执行该工具后情绪向量会移向哪里
                                ← 选择移向"好区域"的工具
```

```python
# 每个 (system, tool) 组合有一个典型效果向量
strategy_effects = {
    ("Bank", "VERIFY_S1"): EmotionVector(0.05, -0.15, -0.05, 0.0, 0.1, 0.0),    # 排他性 → 轻微提笃定
    ("Bank", "VERIFY_S3"): EmotionVector(0.1, -0.1, 0.0, -0.2, 0.05, 0.0),      # 传播溯源 → 提笃定降警觉
    ("Market", "VERIFY_S4"): EmotionVector(0.2, -0.2, -0.1, -0.15, 0.1, 0.0),   # Market 的 S4 效果最强
}

def effect_guided_action(e_now, state):
    best_score = -inf
    best_tool = None
    for tool in state.available_tools():
        Δe = effect_model.predict(state.system, tool.name)
        e_pred = (e_now + Δe).clamp()
        # 评估预测位置：离"理想停止区域"有多远
        score = stop_projection.readiness(e_pred)
        if score > best_score:
            best_score = score
            best_tool = tool
    return best_tool
```

#### 操作 3：停止投影 —— 学习到的决策边界

```
decision_readiness(e) = σ(w · e + b)

w 是一个 6 维向量，它不是手调的，而是从历史数据中学到的：
- 标记历史上那些"停止后结果正确"和"停止后结果错误"的情绪状态
- 用感知器/SGD 更新 w，使正确的停止得分高，错误的停止得分低
```

```python
class StopProjection:
    def __init__(self):
        # 语义先验:
        # 笃定↑→停(+) 好奇↑→继(-) 困惑↑→继(-) 警觉↑→继(-) 饱足↑→停(+) 焦虑↑→停(+)
        self.w = np.array([0.30, -0.10, -0.25, -0.20, 0.20, 0.25])
        self.b = 0.0
        self.threshold = 0.80

    def readiness(self, e: EmotionVector) -> float:
        return sigmoid(np.dot(self.w, e.to_array()) + self.b)

    def update(self, e_stop: EmotionVector, was_correct: bool, lr: float = 0.05):
        """在线 SGD：正确停止→提高得分，错误停止→降低得分"""
        y = self.readiness(e_stop)
        target = 1.0 if was_correct else 0.0
        grad = (y - target) * y * (1 - y)
        self.w -= lr * grad * e_stop.to_array()
        self.b -= lr * grad
```

### 4.4 情绪向量不驱动 if-then，而是驱动向量操作

```
❌ 旧: if anxiety > 0.7 → Strategy A
❌ 旧: if conviction < 0.4 and vigilance > 0.5 → S3

✅ 新: cos(e_now, e_hist) → 检索最相似历史状态的后续最优动作
✅ 新: e_now + Δe_tool → 预测哪个工具推往最佳区域
✅ 新: σ(w·e + b) → 连续停止得分，w 从数据学习
```

## 五、Meta-Controller 推理循环

### 5.1 每步决策

```python
class EmotionVectorMetaController:

    def step(self, state: ControllerState, budget: ResourceBudget) -> ControllerAction:
        # ---- 1. 计算当前情绪向量 ----
        e = compute_emotion_vector(
            state.hypothesis_list,
            budget.remaining_ratio(),
            state.iteration, state.max_iter,
        )
        e = apply_resource_modulation(e, budget.remaining_ratio())

        state.emotion_history.append(e)

        # ---- 2. 硬约束终止 ----
        if budget.exhausted():
            return STOP("budget_exhausted")
        if state.iteration >= state.max_iter:
            return STOP("max_iterations")

        # ---- 3. 停止投影 ----
        readiness = self.stop_projection.readiness(e)
        if readiness > self.stop_projection.threshold:
            return STOP(f"readiness={readiness:.2f}")

        # ---- 4. 向量原生动作选择 ----
        # 对每个可用的 (工具, 目标) 组合评分
        candidates = {}
        for tool in self.available_tools(state):
            for target in self.select_targets(state, tool):
                # A: 余弦相似度检索
                sim_score = self.trajectory_memory.query(e, tool.name,
                                                          state.system,
                                                          state.reason_family)
                # B: 效果向量预测
                Δe = self.effect_model.predict(state.system, tool.name)
                e_pred = (e + Δe).clamp()
                effect_score = self.stop_projection.readiness(e_pred)

                # C: 信息增益估计（作为附加信号）
                ig = tool.estimate_information_gain(state, target)

                candidates[(tool.name, target)] = (
                    sim_score * 0.3 + effect_score * 0.3 + ig * 0.4
                )

        # ---- 5. 抢占规则（仅语义锚点，因是二值信号）----
        if self._has_semantic_signal(state):
            best_tool = next((t for t in self.available_tools(state)
                              if t.name == "VERIFY_S5"), None)
            if best_tool:
                target = state.hypothesis_list.top(1)[0]
                return Action(tool=best_tool, target=target)

        # ---- 6. 选择得分最高的 (工具, 目标) ----
        best = max(candidates, key=candidates.get)
        tool_name, target = best
        tool = self.toolbox[tool_name]

        return ControllerAction(tool=tool, target=target)

    def apply_result(self, state, action, result):
        """执行动作后更新 HypothesisList 和模型。"""
        e_before = state.emotion_history[-1]

        # 更新 HypothesisList
        self._update_hypothesis_list(state.hypothesis_list, action, result)

        # 计算新情绪向量
        e_after = compute_emotion_vector(state.hypothesis_list, ...)

        # 记录效果向量
        Δe = e_after - e_before
        self.effect_model.record(state.system, action.tool.name, Δe)

        # 记录轨迹
        self.trajectory_memory.add(e_before, e_after, action.tool.name,
                                    state.system, state.reason_family)

        state.iteration += 1
```

### 5.2 推理场景示例

```
Case: Bank, GT=Redis02 (high memory usage)

Step 0: 初始状态
  HypothesisList: active=[], reserved=[]

Step 1: ENGINE_SCAN(all_entities[:25])
  → 7 个候选加入 active
  HypothesisList: active=[
    Tomcat01(0.72), Redis01(0.45), Mysql02(0.38), ...]
  Emotion: 笃定=0.4 好奇=0.85 困惑=0.0 警觉=0.5 饱足=0.0 焦虑=0.1

Step 2: VERIFY_S1([Tomcat01, Redis01, Mysql02]) — 排他性
  → Tomcat01: support (异常强于 peer), Redis01: refute (无异于 peer),
     Mysql02: support
  HypothesisList: Tomcat01(0.78↑), Mysql02(0.42↑),
                  Redis01(0.25↓) → reserved
  Emotion: 笃定=0.5 好奇=0.7 困惑=0.0 警觉=0.4 饱足=0.1 焦虑=0.15

Step 3: GRAPH_EXPAND(Tomcat01, "upstream") — 探索依赖
  → 发现 IG01, MG01 是 Tomcat01 的上游依赖
  HypothesisList: active+=[IG01(0.25), MG01(0.25)]  ← 新候选加入
  Emotion: 笃定=0.45 好奇=0.75 困惑=0.0 警觉=0.45 饱足=0.1 焦虑=0.2

Step 4: VERIFY_S3(Tomcat01) — 传播溯源
  → 上游 IG01 异常比 Tomcat01 更早更强 → Tomcat01 可能是受害者
  Tomcat01: support→refute ↓, IG01: inconclusive→support ↑
  HypothesisList: IG01(0.55↑), Tomcat01(0.48↓), Mysql02(0.42)
  Emotion: 笃定=0.3↓ 好奇=0.65↓ 困惑=0.2↑ 警觉=0.7↑ 饱足=0.2 焦虑=0.25
           ↑ 排名翻转，情绪响应：笃定下降，警觉上升

Step 5: ENGINE_RECOVER(IG01) — 对新领头候选做精确评估
  → recovery=0.91 强信号！
  HypothesisList: IG01(0.88↑)  ← 大幅提升
  Emotion: 笃定=0.8↑ 好奇=0.4 困惑=0.1 警觉=0.2↓ 饱足=0.4 焦虑=0.15
           ↑ 笃定大幅上升，警觉下降

Step 6: VERIFY_S5(IG01) — 语义锚点确认
  → 日志发现 "OOM killed" + "allocation failure" → 硬证据
  IG01(0.88→0.95↑)
  Emotion: 笃定=0.93 饱足=0.8  → 停止投影触发
  STOP: IG01 (high memory usage / JVM OOM)
```

注意：
- 候选列表在每一步都在变化：添加新候选、排名翻转、降级到 reserved
- 情绪向量自然响应信念变化：排名翻转→笃定降警觉升，强证据→笃定升
- 语义锚点（S5）总是在有信号时抢占

## 七、LLM Agent 扩展性

### 7.1 工具接口统一

```python
class BaseTool(ABC):
    """工具接口。当前算法实现和未来 LLM Agent 实现共用。"""
    name: str
    cost_profile: ResourceCost

    def execute(self, state, target) -> ToolResult: ...
    def estimate_information_gain(self, state, target) -> float: ...


# ---- 当前：算法实现 ----
class VerifyS1Algorithmic(BaseTool):
    name = "VERIFY_S1"
    def execute(self, state, target):
        return self._compute_peer_exclusivity(target.entities, ...)

# ---- 未来：LLM Agent 实现 ----
class VerifyS1Agent(BaseTool):
    name = "VERIFY_S1"
    def __init__(self, llm_client, agent_profile):
        self.llm = llm_client
        self.philosophy = agent_profile["philosophy"]

    def execute(self, state, target):
        prompt = self._build_prompt(state, target)
        response = self.llm.generate(prompt)
        return self._parse_verdict(response)

    def estimate_information_gain(self, state, target):
        # LLM Agent 可以自己估计 IG，也可以使用默认启发式
        return self._default_ig_estimate(state, target)
```

### 7.3 Meta-Controller 不感知 Agent 差异

meta-controller 只通过 `BaseTool` 接口消费工具的输出。工具是算法还是 LLM Agent、Agent 的 philosophy 如何——meta-controller 完全不关心。这让策略池可以渐进式地从算法迁移到 Agent：先替换 S5（语义理解最自然适合 LLM），再替换 S2/S3（需要多信号综合推理），最后替换 S1/S4。

## 八、资源约束

双层约束机制：

| 层次 | 类型 | 机制 |
|------|------|------|
| **硬约束** | `budget.exhausted()` | 物理资源（API calls / tokens / time）耗尽 → 强制 STOP |
| **软调制** | 情绪向量的连续调制 | 预算消耗 → 焦虑↑ 好奇↓ 饱足↑ → 决策倾向自然保守 |

```python
def apply_resource_modulation(e, budget_remaining_ratio):
    pressure = 1 - budget_remaining_ratio
    e.anxiety   = clamp(e.anxiety + pressure * (1 - e.conviction) * 0.5)
    e.curiosity = clamp(e.curiosity - pressure * e.curiosity * 0.4)
    e.satiety   = clamp(e.satiety + pressure * 0.3)
    return e
```

资源充足时，情绪完整反映证据状态。资源紧张时，情绪自然趋向保守——**但证据结构从不会被硬阈值覆盖**。
